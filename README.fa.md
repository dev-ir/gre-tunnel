# DVHOST GRE Tunnel v3.0.0 (آزمایشی)

**🌐 زبان‌ها:** [English](README.md) | **فارسی** | [Русский](README.ru.md)

![پیش‌نمایش محیط GRE Tunnel](assets/terminal-preview.svg)

*تصویر بالا پیش‌نمایش طراحی است و اطلاعات سرور نمونه هستند.*

## معرفی
نسخه ۳ امکان ساخت تونل‌های GRE مستقل از **یک سرور ایران به چند سرور خارج** را فراهم می‌کند. این برنچ در حال توسعه است؛ پیش از استفاده عملیاتی روی سرور آزمایشی تست کنید. **منو و خروجی اسکریپت فقط انگلیسی است.**

## آمادگی در برابر محدودیت ارتباط بین‌الملل

گزینه **6 — Iran-access readiness / path diagnostics** مسیر عمومی هر سرور خارج، پاسخ ICMP از IP داخلی و عمومی آن، DNS و دسترسی HTTPS خارجی را بررسی می‌کند. این ابزار **فقط عیب‌یابی می‌کند** و تونل‌ها، روتینگ یا فایروال را تغییر نمی‌دهد. پاسخ‌ندادن به پینگ الزاماً به معنی قطعی ارتباط نیست.

برای افزایش تاب‌آوری، حداقل دو سرور خارج از دیتاسنترها و شبکه‌های متفاوت داشته باشید و برای مدیریت سرورها یک مسیر مستقل در نظر بگیرید. جابه‌جایی ترافیک بین تونل‌ها باید در لایه سرویس/اپلیکیشن طراحی شود و **هنوز در این نسخه خودکار نیست**. اگر مسیرهای بین‌المللی به‌طور کامل قطع شوند، GRE به‌تنهایی نمی‌تواند مانع «ایران‌اکسس» شدن شود.

## امکانات
- سرویس systemd جداگانه برای هر تونل (`dvhost-gre-v3-greXX.service`)
- ایجاد و مدیریت تونل با `ip tunnel` بدون اجرای سراسری `netplan apply`
- اختصاص یک شبکه خصوصی `/30` به هر تونل
- بررسی IP عمومی انتخاب‌شده، مسیر مقصد و تداخل نام و Subnet قبل از نصب
- بازگردانی تغییرات همان تونل در صورت شکست ساخت یا فعال‌سازی دائمی
- عدم تغییر تنظیمات تونل‌های نسخه ۲

## اجرا
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/dev-ir/gre-tunnel/v3.0.0/main.sh)
```

پیش‌نیازها: لینوکس، دسترسی root، systemd، ابزارهای `iproute2` و `modprobe`. پروتکل **GRE (شماره ۴۷)** باید در فایروال و شبکه دیتاسنتر مجاز باشد.

### مثال اتصال ایران به دو سرور خارج
| سرور | نام اینترفیس نمونه | IP داخلی |
|---|---|---|
| ایران ← خارج اول | `gre01` | `10.50.1.1/30` |
| خارج اول ← ایران | `gre01` | `10.50.1.2/30` |
| ایران ← خارج دوم | `gre02` | `10.50.2.1/30` |
| خارج دوم ← ایران | `gre01` | `10.50.2.2/30` |

در هر دو طرف یک تونل، **Subnet یکسان** و نقش متناسب ایران/خارج را انتخاب کنید. نام اینترفیس‌ها در سرورهای مختلف لازم نیست یکسان باشد.

## محدودیت‌های فعلی
- تونل‌های جدید از طریق سرویس اختصاصی systemd پس از راه‌اندازی شبکه اجرا می‌شوند و Netplan آن‌ها را مدیریت نمی‌کند.
- مهاجرت خودکار تونل‌های نسخه ۲ انجام نمی‌شود و این نسخه تنظیمات آن‌ها را حذف نمی‌کند.
- اگر روتینگ یا ابزارهای شبکه دیگر تداخل داشته باشند، احتمال اختلال وجود دارد.
- اطلاعات کشور و ISP از سرویس خارجی دریافت و تا ۲۴ ساعت کش می‌شود؛ ممکن است در دسترس نباشد. IP هدر از مسیر محلی خوانده می‌شود.
- مانیتورینگ پیشرفته، تاریخچه قطعی و بازیابی هوشمند هنوز کامل نشده‌اند.
- **GRE رمزنگاری ندارد.** برای ترافیک حساس باید امنیت مسیر جداگانه تأمین شود.
- مسیر `/usr/bin/ip` باید در توزیع مورد استفاده موجود باشد.
- این نسخه هنوز در محیط عملیاتی تأیید نشده است.
